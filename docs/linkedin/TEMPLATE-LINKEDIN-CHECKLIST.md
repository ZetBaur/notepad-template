# ШАБЛОН: чеклист профиля LinkedIn для нового профиля

Чистый образец (без фактов `backend`). Копируется для каждого нового профиля/позиции: `cp docs/linkedin/TEMPLATE-LINKEDIN-CHECKLIST.md profiles/<профиль>/linkedin/CHECKLIST.md` (или в корень как `LINKEDIN-CHECKLIST-<профиль>.md`). Эталон с историей решений — `docs/linkedin/LINKEDIN-PROFILE-CHECKLIST.md` (backend). Резюме — `docs/resume/TEMPLATE-RESUME-CHECKLIST.md`. Поведение в LinkedIn (запросы в контакты, сообщения, отклики, ответ на отказ) — `docs/linkedin/LINKEDIN-ACTIVITY-RULES.md`, здесь только оформление профиля.

## Правила ведения чеклистов LinkedIn (читать первым; действуют для всех 4 файлов)
**Режим — РАЗБОР:** пункты обсуждаются по одному («добавлять» / «не добавлять»). Режим СБОР (вносить материалы без оценок) включается только по просьбе пользователя.

**Что делать, когда владелец прислал материал (режим СБОР):**
1. Прочитать этот блок и нужные разделы чеклистов (файл целиком не читать: он большой, искать `grep`).
2. Назначить источнику следующий номер В<n> (см. «Статус» ниже) и записать его в «Источники» всех файлов, куда попадут пункты.
3. Внести **все** рекомендации автора пунктами `- [ ]` с источником, временем (если есть) и пометкой «гипотеза»; без своих оценок и без сверки с текущим профилем. Перед записью проверить дубли (grep по ключевым словам); дубль не вносить, а написать одной строкой, что уже есть.
4. Куда класть пункт, решает агент по логике: про профиль/About — во все чеклисты и в шаблон; про бизнес (ниша, лиды, email, оффер, продажи) — только в бизнес-чеклисты; про посты — notepad и бизнес.
5. Противоречие с уже записанным → строка «источник ↔ источник» в разделе «Противоречия между источниками» (во всех затронутых файлах). Решим при создании/обновлении профиля. Отметка «возможное» — расхождение неочевидно.
6. Рекламу автора (курсы, свои инструменты, результаты учеников) помечать как рекламу. Советы = гипотезы.
7. Ответ владельцу: коротко, простыми словами, по-русски: списком «о чём материал и что рекомендуют», затем что внесено и куда, затем новые противоречия. Один вопрос за раз. В конце «Можно /clear» или «Пока не чисти: …».
8. Профиль в LinkedIn не менять, пока владелец не скажет «начинаем правки».

**Роли:** этот файл — пользователь как соискатель (пассивный поиск: профиль настроен так, чтобы рекрутёры писали сами). Поведение в LinkedIn — `LINKEDIN-ACTIVITY-RULES.md`.

**Статус:** источники пока не внесены. **Следующий номер — В1.**

## Как пользоваться
1. Пройти сверху вниз. У критерия: **что проверить** (простыми словами), **как проверить**, **статус** (`[ ]` не сделано, `[~]` частично, `[x]` + дата + как проверено, `[н/п]` не применимо + причина).
2. **Факты о владельце — только его.** Выдумка (компании, цифры, навыки, должности) не берётся: ломается на первом уточняющем вопросе и на проверке бэкграунда.
3. **Все критерии — гипотезы** (советы блогеров и консультантов, не проверенные данные). Проверка — свои метрики в `profiles/<профиль>/analytics.md`: просмотры профиля, появления в поиске, сообщения рекрутёров, интервью. Менять **один блок за раз**, записывать версию и дату в `changes.md`, сравнивать «до/после» не раньше чем через 1–2 недели. Пока идёт замер версии, блоки замера не трогаем.
4. Решения владельца ведём по одному пункту: что за совет, что уже есть, источник, как проверить, рекомендация агента, ответ владельца.
5. Тексты профиля лежат в `profiles/<профиль>/linkedin/` (about, headline, experience-*.md). В LinkedIn их вносит владелец сам.

## 1. Основа профиля
- [ ] **Профиль = поисковая карточка:** каждый блок (headline, About, Experience, Skills) заполнен словами, которые ищут рекрутёры (должности, навыки, технологии, локация); чем полнее профиль, тем чаще он в выдаче (гипотеза, источник — бывший сотрудник LinkedIn, без цифр). Проверка: появления в поиске в `analytics.md` до/после правок.
- [ ] **Красивая ссылка** `linkedin.com/in/имя-фамилия` (Edit public profile & URL). Если по решению владельца имя в профиле скрыто/изменено (чтобы текущий работодатель не нашёл), записать риски: правило LinkedIn про настоящее имя, фамилия видна в ссылке, имя в резюме не совпадает с профилем.
- [ ] **Язык профиля = язык целевого рынка** (обычно English), весь текст на нём.
- [ ] **Public profile включён**, видимые блоки на Allow (иначе профиль не находится вне LinkedIn и в поиске).
- [ ] **Industry** выбран по профилю (например Software Development).
- [ ] **Фото:** деловое, нейтральный светлый фон, без котиков/аниме/пляжа; лицо крупно. Настройка видимости фото — решение владельца. Фото не вредит на западных рынках для B2B-контракторов (гипотеза, мнение блогеров).
- [ ] **Баннер:** свой, не стоковая картинка. Вариант: нейтральный красивый или «роль + годы + главные технологии + 1–2 реальные заслуги»; без лишнего.
- [ ] **Нет юникодного «жирного» и «курсива»** (символы из генераторов boldtextgenerator, U+1D400–1D7FF: 𝗟𝗶𝗸𝗲 𝘁𝗵𝗶𝘀): по данным автора канала (2026-09-06, без источника) LinkedIn их не индексирует, слово в поиске не находится. Только обычный текст во всех блоках. Проверка: скрипт по диапазону U+1D400–1D7FF в текстах профиля.

## 2. Headline, локация, годы опыта
- [ ] **Формула headline:** должность (уровень) → годы опыта → 2–3 ключевых технологии/специализации → направление → фраза «что и какого масштаба делаю» с цифрой. Образец: `Senior Backend Engineer (10+ years) | Node.js, TypeScript | High-Load | Kafka | AWS | Delivering X at Y scale`. Лимит headline — 220 символов. Только реальное: «Staff» без фактов не ставить, «Ex-» только настоящие компании.
- [ ] **Слова в headline берутся из реальных вакансий** целевой роли: выписать топ-10 навыков из 10–15 вакансий, сверить с headline. Ставить те, что владелец реально знает.
- [ ] **Один основной стек (T-shape),** смежные «паровозиком»; не раздувать 5–6 стеков. Побочный фронтенд/мобайл не торчит в headline, топ-навыках и About.
- [ ] **Локация** соответствует целевому рынку (страна влияет на ставки и на поиск рекрутёров). Решение владельца записано.
- [ ] **Годы опыта видны** в headline и первой строке About (для больших вилок рекрутёры ищут 7+ лет; на контрактах «5 лет не считается Senior»).

## 3. About
- [ ] **Структура:** (1) кто ты + годы → (2) крючок про «боль» работодателя (схема PAS: проблема → я помогаю её решить) → (3) 2–3 результата с цифрами → (4) позиционирование (где силён) → (5) что ищешь + как связаться (формат работы: remote / B2B / relocation — только то, что правда). Не автобиография (родился/учился/женился).
- [ ] **Без пустых качеств** («responsible», «stress-resistant», «team player»), без хобби-пустышек, без финального клише «looking for new challenges».
- [ ] **Без эмодзи-значков**, аккуратные переносы строк.
- [ ] **Список технологий в конце — только то, что владелец реально знает** (совет «добавь даже незнакомые» не берём).
- [ ] **Контакты в About:** email — решение владельца (риск спама; рекрутёры пишут в LinkedIn). Решение записано.
- [ ] **Слов-маркеров ИИ нет** (см. раздел 8 в `docs/resume/TEMPLATE-RESUME-CHECKLIST.md`).
- [ ] **About писать от первого лица** («I help…», «my results»), не в третьем («Baur is an expert…») (В11, 2026-10-10, решение владельца «добавлять»). Гипотеза, стилистический совет без данных. Влияет на доверие и ответы.
- [ ] **Профиль — личный сайт/бренд, а не только онлайн-резюме;** LinkedIn нужен не только тем, кто ищет работу: люди узнают, чем ты занят, и к тебе приходят возможности (В11, 2:45–3:15; 4:30–5:00). Гипотеза.
- [ ] **Заполнять все блоки метаданных,** включая опыт, навыки, рекомендации, волонтёрство, локацию: рекрутёр ищет по месту, навыкам и прошлому опыту, и чем больше заполнено, тем чаще профиль в выдаче (В11, 5:00–6:05). Дополняет пункт 1 раздела «Основа».
- [ ] **Начать хотя бы с короткого About (1–3 предложения):** «что-то лучше, чем ничего»; в её классе в Stanford About не заполнен у 30–50% (В11, 8:50–9:45; 18:10–18:25).
- [ ] **Конкретика «one in a million», а не «one of a million»:** About должен подходить только одному человеку (конкретные факты и достижения вместо общих слов) (В11, 11:38–12:10; 18:27–18:35).
- [ ] **Цифры в About и резюме:** чем больше конкретных чисел (рейтинг, годы, размер компаний, привлечённые деньги), тем лучше (В11, 10:45–11:00; 24:11–24:45).
- [ ] **Короткие пункты вместо абзацев:** легко читать и запоминать; писать коротко труднее, чем длинно (особенно с AI), но лучше (В11, 21:05–22:00).
- [ ] **Эмодзи по смыслу, не случайные** (стрелка — про стрельбу из лука, мяч — про баскетбол): ломают «стену текста» и делают текст менее похожим на AI; AI вставляет случайные эмодзи (В11, 22:00–22:50). Расходится с В1 (без эмодзи), см. «Противоречия».
- [ ] **Личный штрих в About:** необычные факты о себе (хобби, занятия) делают запоминающимся и дают тему для разговора; пример с Uber-рейтингом 4.98 делит аудиторию 50/50 (кринж или симпатично) (В11, 12:12–12:50; 15:39–17:10; 22:56–23:20; 28:35–29:15).
- [ ] **Доля личного и смайлики зависят от уровня:** старшим можно больше личного и смайлик; младшим, кто хочет выглядеть серьёзнее, меньше эмодзи и больше профессионального (В11, 12:30–12:55; 17:25–18:10).
- [ ] **CTA (призыв к действию) в конце About:** выбрать, чего хочешь от читателя (подписаться, написать, сотрудничество), и дать способ (контакт, email) (В11, 13:20–13:50; 27:37–28:30). Расходится с решением «email в About не добавляем», см. «Противоречия».
- [ ] **Миссия вверху About:** что для тебя важно и зачем; не только перечень опыта, а «почему» (В11, 25:50–27:35; по её словам, это отметил её профессор как один из лучших About). Вопрос из подкаста: что для тебя важнее всего и почему.
- [ ] **Смелые заявления должны подтверждаться остальным профилем** (ссылки, компании, опыт): тогда допустимо писать цель вперёд («в процессе создания…») (В11, 14:50–15:30).
- [ ] **Не писать общие фразы** («Passionate about solving complex product challenges, collaborating, and driving results», «I welcome conversations of any kind»): звучит как AI (В11, 30:45–31:20).
- [ ] **Блок ключевых слов внизу About (advanced-приём):** в её примере внизу идёт длинный список терминов, которые ищут рекрутёры (технологии, роли, компании, школы), с пометкой, что это тест SEO; автор не советует случайный список, только термины, применимые к тебе и связанные с профилем; доказательств нет, ссылается на знание устройства LinkedIn Jobs и профилей (В11, 30:35–33:50). В примере были и компании, где человек не работал.
- [ ] **Не использовать AI-генератор LinkedIn для About:** её собственные тексты лучше; AI-кнопка — запасной вариант «Hail Mary», когда нет времени (В11, 34:13–34:55).
- [ ] **Упражнение «одна фраза»:** открыть профиль и ответить, какую одну фразу люди запомнят после About; не получается ответить легко — вернуться к простым версиям и переписать (В11, 36:36–37:00).

## 4. Experience (опыт работы)
- [ ] **Схема каждого места:** `Company:` (что за компания + масштаб) → `Core Responsibilities` (3–4 строки с ярлыком) → `Key Accomplishments` (ярлык + метод + цифра «было → стало» + срок) → `Key Skills & Tools`. В названии должности стек в скобках, если помогает («Backend Engineer (Node.js / TypeScript)»).
- [ ] **Один буллет — одна мысль, до ~25 слов, простой английский** (те же правила, что в `docs/resume/TEMPLATE-RESUME-CHECKLIST.md`, раздел 5). Длинные буллеты с 3–4 фактами разбивать на два.
- [ ] **Цифры:** реальные, объяснимые; ценность по порядку: деньги → пользователь → система → активность. Красные флаги: все числа круглые, ложная точность, нет цифр совсем.
- [ ] **Строка `Key Skills & Tools`** у места — спорный пункт: по одному мнению, список технологий мешает читать (данных нет); в LinkedIn это поисковые слова. По умолчанию оставить, менять только по замеру.
- [ ] **Домен компании виден** (fintech, healthcare, e-commerce); доменные слова (LLM, IoT, payments) в описании.
- [ ] **У каждого места привязаны навыки** (5–10 самых востребованных).
- [ ] **Все компании с названием**, не «NDA»; нет Junior/Middle, если рост виден; места дольше ~1,5 лет (частые смены по году — минус).
- [ ] **Ссылки на материалы** (портфолио, статья, презентация, сертификат) — только публичное и без NDA; если прикрепить нечего, пункт не применим.
- [ ] **Соответствие резюме:** названия, даты, цифры, компании, локации совпадают с резюме.

## 5. Skills
- [ ] **Top 5 skills** закреплены и совпадают с целевыми вакансиями.
- [ ] **Общий список** большой (потолок LinkedIn — 100; ориентир 50–60+), только реально известное на уровне, который владелец объяснит на интервью; навыки привязаны к местам работы, где применялись. Смежные навыки (в том числе фронтенд) в общем списке допустимы, наверху (Top 5, headline, About) остаётся основной стек.
- [ ] **Нет «вымышленных» навыков** и технологий «на уровне чтения кода» как основного стека.

## 6. Образование, сертификаты, контакты, рекомендации
- [ ] **Education заполнено** (вуз, степень, годы); вуз не обязан быть зарубежным. Расхождение с резюме по годам осознанное и записано.
- [ ] **Сертификаты:** только реально пройденные и релевантные; нет релевантных — не добавляем.
- [ ] **Contact info:** ссылка на профиль, GitHub/портфолио, простая почта; телефон/мессенджер — решение владельца (по умолчанию «в личке по просьбе рекрутёра»).
- [ ] **Рекомендации:** только от бывших коллег и только если человек готов; просить всех подряд смысла нет. Список людей для проверки рекомендаций — у владельца, в файлы не пишем (личные данные).
- [ ] **Languages/IELTS:** решение владельца (по умолчанию не добавляем, если нет теста; для резюме строка языков есть).
- [ ] **Interests / Top voices:** не берём, если нет данных о пользе.

## 7. Настройки и статусы
- [ ] **Open to Work:** режим «Recruiters only» без баннера на фото (баннер на фото блогеры называют red flag — гипотеза). Решение принимается по замеру сообщений рекрутёров до/после.
- [ ] **Кто может написать** (Settings → Data privacy → Who can reach you → Messages you receive): Message requests, InMail, Open Profile messages, Job invitation messages — включены; иначе письма рекрутёров не из контактов не дойдут.
- [ ] **Share profile updates:** по умолчанию Off (чтобы лента контактов, включая текущего работодателя, не видела правки).
- [ ] **Discoverability** по email и телефону — решение владельца.
- [ ] **Invitations to connect:** Everyone on LinkedIn.
- [ ] **Резюме в LinkedIn загружается последним шагом** (когда профиль и резюме готовы): Settings → Data privacy → Job seeking preferences → Resumes and application data; «Share resume data with hirers» — решение владельца (учесть: в файле настоящее имя). Эффект «SEO» не доказан.
- [ ] **LinkedIn Premium:** только как замер (бесплатный месяц: просмотры, появления в поиске, сообщения неделю до и 2–3 недели с Premium). Покупаем платно только если замер покажет рост; автопродление отключить в тот же день (платное — подтверждает владелец).

## 8. Активность и контент (после замера)
- [ ] **Посты:** эксперимент — 2 недели, 3–5 коротких технических постов в неделю по реальным темам владельца, 1 эмодзи, вопрос в конце, умеренные хештеги по реальным темам. Замерять показы, просмотры профиля, появления в поиске, сообщения рекрутёров. Не копировать драматичные чужие истории.
- [ ] **SSI** не цель: данных, что он влияет на отклики, нет.
