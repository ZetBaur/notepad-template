Тренировка собеседования голосом. Отвечай коротко, простыми словами, **один вопрос за раз**. Цель: пользователь учится говорить своими словами по тезисам, которые бот показывает в панели. Базу не меняй без «ок». В браузер не лезь.

Аргументы: `[профиль] [язык]`. Профиль — как в `profiles/<профиль>/bot/knowledge.md` (не назван — единственный, иначе спроси). Язык вопросов по умолчанию английский (голос `Samantha`); русские вопросы — голос `Milena` (проверь `say -v '?'`). Русский текст только русским голосом.

## 0. Проверка базы знаний (без неё мок не начинается)
Прочитай `profiles/<профиль>/bot/knowledge.md` (по заголовкам `grep -n "^#"`, целиком не читай) и посчитай. Не запускайся, пока все пункты не выполнены:
1. **Часть 1 заполнена на 100%:** «Кто и условия», «Опыт», «Стек», «Как работает» без пустых мест и без `<!-- … -->`-заглушек. Это факты — порога нет.
2. **Покрытие вопросов ≥ 90%:** из пунктов `docs/bot/QUESTIONS-LIST.md` (одинаковые по смыслу варианты — один вопрос) не меньше 90% имеют готовый ответ в Части 2. Соответствие определяй по смыслу заголовка.
3. **Остаток (≤ 10%) записан в `profiles/bot/GAPS.md`.** Нет там вопроса — допиши сам.
4. **Формат ответов:** не меньше 90% готовых ответов — 3–5 коротких фраз по 8–15 слов, каждая с новой строки.
5. **Запреты:** `node app/agent-sidecar/eval/check-kb.mjs` без нарушений (код выхода 0).
6. **Тест бота:** есть прогон `eval` без провалов по этому профилю после последней правки базы (`app/agent-sidecar/eval/out/results.json`; нет файла или он старее `knowledge.md` — предложи навык `eval`).

Покажи таблицей: пункт · итог · что не хватает («Покрытие: 41 из 62 = 66%, нужно ≥ 56; не хватает: …»). Если что-то не выполнено — **не начинай мок**, скажи: «База ещё не готова для мока. Сначала отполируем её» и предложи сразу пройти недостающие вопросы по одному (так же, как в `/setup-profile`, шаг 4: черновик из фактов → один вопрос → запись после «ок»). Когда пункты выполнены — иди к шагу 1.

## 1. Подготовка (не говори «готово» за пользователя)
- Проверь, запущено ли приложение: `pgrep -x notepad`. Нет — попроси запустить `/Applications/Notepad.app` (или `pnpm dev` в `app/`).
- Попроси настроить: выбрать профиль `<профиль>`, компанию — без выбора или нужную, включить захват звука с колонок (чтобы приложение слышало `say`), очистить панель ответов.
- Если есть `profiles/<профиль>/mock-progress.json` — скажи одной строкой, сколько вопросов помечено «слабо»; они пойдут первыми.
- Жди слово «готово».

## 2. Банк вопросов (собери сам, пользователю покажи только числа)
Источники:
1. **Реальные интервью:** `profiles/interviews/transcripts/*.md` (строки `- HH:MM текст`, речь интервьюера). Пропусти: приветствия и проверки звука (до ~4 слов, «can you hear me»), и строки, совпавшие с вопросами из `app/agent-sidecar/eval/questions*.json` (это были озвученные тесты, не живые интервью). **Длинный монолог интервьюера** = 35+ слов; такие обязательно включай и озвучивай целиком.
2. **Список** `docs/bot/QUESTIONS-LIST.md`: поведенческие разделы и технические ML/AI (Python и данные, основы ML, LLM/RAG/агенты, MLOps, System Design для ML).
3. **Тестовые вопросы** `app/agent-sidecar/eval/questions-<профиль>.json` (нет файла — `questions.json`): `tech` для технического блока, `behav` / `border` / `company` для поведенческих.
Дубликаты и перефразировки одного вопроса объедини. Тип (поведенческий / технический) определи по смыслу.

## 3. План
- Поведенческие: все, блоками по **10**. Первый блок начинается с открывашки и «Tell me about yourself», дальше случайно; в каждом блоке по возможности есть 1–2 длинных монолога. Слабые из прошлых прогонов — в первом блоке.
- Потом **10 технических**: сначала из реальных интервью, затем из вопросов профиля; слабые вперёд.
- Покажи план одной строкой: «Поведенческих N (блоков B), технических 10, длинных монологов M». Тексты не показывай.

## 4. Цикл (по одному вопросу)
1. `say -v <голос> "<вопрос>"` (длинный монолог — целиком, блокирует до конца речи). Номер вслух не говорить.
2. Напечатай: «Вопрос k из N (блок X). Отвечай вслух и смотри тезисы в панели. Напиши: **дальше** · **повтори** · **слабо** (не смог ответить / запнулся) · **пропусти** · **покажи** (текст вопроса) · **стоп**». Затем **жди** ответа пользователя. Следующий вопрос — только после «дальше» или «слабо» (или «пропусти»).
3. «повтори» — озвучь тот же вопрос ещё раз. «слабо» — пометь вопрос и иди дальше. Пользователь вставил ответ из панели — оцени его одной строкой по `profiles/bot/FORBIDDEN.md`, `GAPS.md` и фактам базы (не выдумка ли); сам не проси.
4. **Уточнение.** Примерно после каждого третьего вопроса озвучь короткое уточнение, как живой интервьюер: «А подробнее?», «Какой был результат?», «Что бы сделали иначе?», «Какая была метрика / baseline?». Бот на него тоже даёт тезисы, пользователь отвечает по ним так же. Жди «дальше».
5. После каждого блока из 10: одна строка итога (озвучено, слабых) и вопрос «Следующий блок? (да / стоп)».

## 5. Итог
- Сохрани отчёт в `profiles/<профиль>/mock/<YYYY-MM-DD-HHMM>.md`: список вопросов, пометки «слабо», пропущенные.
- Обнови `profiles/<профиль>/mock-progress.json`: `{ "weak": ["<вопрос>", …] }` — слабые добавь, вопросы, на которые в этот раз ответил нормально, убери.
- По слабым спроси **одним вопросом**, в чём беда: нет ответа в базе, ответ длинный или бот выдумал. Нет ответа — запиши вопрос в `profiles/bot/GAPS.md` и задай пользователю вопросы для ответа; правки базы вноси после «ок», затем запусти навык `eval`.
- **Закрытие пробелов.** Если в `GAPS.md` по этому профилю есть вопросы, коротко скажи: «Остались N вопросов без ответа в базе. Давай заполним сейчас?» Нет — закончи. Да — задавай **по одному**: вопрос по-русски простыми словами (где, в какой компании и проекте, что сделал, какой результат), пользователь отвечает своими словами; ты пишешь черновик ответа в формате базы (EN, 3–5 фраз по 8–15 слов, каждая с новой строки, только его факты); после «ок» записываешь в `knowledge.md`, вычёркиваешь из `GAPS.md`. Не помнит — оставь в GAPS. В конце напомни «Reload knowledge» в настройках и запусти навык `eval`.
- Последняя строка: «Отчёт: mock/<файл>. Можно /clear.»
