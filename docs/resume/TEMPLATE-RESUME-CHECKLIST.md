# ШАБЛОН: чеклист резюме для нового профиля

Чистый образец (без фактов `backend`). Копируется для каждого нового профиля/позиции: `cp docs/resume/TEMPLATE-RESUME-CHECKLIST.md profiles/<профиль>/resume/CHECKLIST.md` (или в корень как `RESUME-CHECKLIST-<профиль>.md`). Эталон с историей решений — `docs/resume/RESUME-CHECKLIST.md` (backend). Профиль LinkedIn — `docs/linkedin/TEMPLATE-LINKEDIN-CHECKLIST.md`. Что делать в LinkedIn (запросы, сообщения, отклики) — `docs/linkedin/LINKEDIN-ACTIVITY-RULES.md`.

## Как пользоваться
1. Пройти сверху вниз. У каждого критерия: **что проверить** (простыми словами), **как проверить**, **статус профиля** (`[ ]` не сделано, `[~]` частично, `[x]` + дата + как проверено, `[н/п]` не применимо + причина).
2. **Факты о владельце — только его.** Выдуманные компании, должности, цифры, технологии не берём: выдумка ломается на первом уточняющем вопросе и на проверке бэкграунда. Каждую цифру и каждый буллет владелец должен суметь объяснить на интервью.
3. **Все критерии ниже — гипотезы** (советы консультантов и блогеров, не доказанные данные). Проверка — свои метрики: приглашения и ответы рекрутёров до/после смены версии резюме (`profiles/<профиль>/analytics.md`). Менять по одному блоку и записывать версию, иначе замер не сравнить.
4. Резюме и профиль LinkedIn должны совпадать по названиям, датам и цифрам (раздел 11).
5. Решения владельца («добавлять / не добавлять») ведём там же, по одному пункту: что за совет, что уже есть, источник, как проверить, рекомендация агента, ответ владельца.

## 1. Формат и читаемость (человек и ATS)
- [ ] **Простой документ:** чёрный текст на белом, один обычный шрифт (Arial / Calibri / Times), одна колонка, буллеты, до 2 страниц (для 10+ лет опыта; для меньшего опыта — 1 страница). Проверка: открыть docx/PDF, выделить весь текст, вставить в простой блокнот — порядок сохранился.
- [ ] **Без таблиц, колонок, текстовых блоков, иконок, шкал навыков («4 из 5»), фото, графики, картинок с текстом внутри.** Парсеры путают таблицы и колонки, читают слева направо и сверху вниз. Резюме в виде картинки (экспорт из Canva) не читается совсем.
- [ ] **Текстовый PDF** (текст выделяется) или `.docx`; не скан и не картинка. Имя файла по имени владельца (`NAME SURNAME.pdf`).
- [ ] **Стандартные заголовки разделов:** Summary, Skills, Experience, Education. Робот ищет именно их.
- [ ] **Нет скрытого белого текста с ключевыми словами.** Рекрутёры подсвечивают, парсеры видят; бан и недоверие.
- [ ] **Проверка парсером:** текст из PDF по порядку, без «мусора» (бесплатный онлайн-ATS-чекер — только с разрешения владельца, данные уходят наружу).

## 2. Шапка
- [ ] **Имя, одна строка с должностью, страна/город, формат работы** (on-site / remote / hybrid), почта, ссылка на LinkedIn, GitHub/портфолио (если сильное).
- [ ] **Должность один в один как в целевой вакансии** (гипотеза: «Senior X» против «X» даёт разное число приглашений). Только перевод реальной роли, **не повышение уровня** (риск при проверке бэкграунда). Если официальный титул и желаемая роль расходятся — решение владельца, записать основание.
- [ ] **Почта по имени**, не рабочая и не «случайная». Низкий приоритет.
- [ ] **Без возраста, даты рождения, семейного статуса, пола, национальности; фото — только по рынку** (США, Великобритания, Канада, Австралия — без фото; Франция, Швеция — можно).
- [ ] **Полный адрес не нужен:** страна (и город при необходимости) и формат работы.
- [ ] Степень рядом с именем (BSc/MSc) — только если вакансия явно требует диплом и он по профилю.

## 3. Summary / Career Profile
- [ ] **3–8 строк, связными предложениями, не списком через запятую.** Структура: (1) кто ты и уровень (роль + годы); (2) главная экспертиза и стек; (3) главный результат с цифрой.
- [ ] **Ключевые слова вакансии стоят в первых двух предложениях** (только те, которыми владелец реально пользовался).
- [ ] **Без пустых качеств** («responsible», «stress-resistant», «team player», «fast learner», «hardworking»). Эти качества доказываются буллетами, а не заявляются.
- [ ] **Не «Objective»** («хочу найти достойную позицию»): работодателя волнует, что он получит.
- [ ] Проверка: «если рекрутёр прочтёт только эти 3 строки, поймёт ли он мою главную ценность?»

## 4. Career Highlights (необязательно, если хватает места)
- [ ] **2–3 строки: глагол + что сделал + цифра «было → стало».** Берём самые сильные результаты из опыта. Повторов с Summary нет.
- [ ] **Необязательный вариант (если влезает в 2 страницы):** блок «Key Experience» по типам задач (например: производительность, надёжность, расходы, команда), а не по компаниям; хронология ниже как подтверждение. Для `backend` не нужен (Highlights уже покрывает), для профиля со сменой сферы или с разнородным опытом может быть полезен.

## 5. Опыт работы (Experience)
- [ ] **Обратный хронологический порядок.** Формат места: компания (что за компания и масштаб) → должность → даты → 1–2 строки контекста → буллеты.
- [ ] **Формула буллета:** сильный глагол прошедшего времени → что сделал и на какой технологии → метрика «было → стало» → выгода/срок. Не «improved performance significantly» и не «by 40%» без объекта. Метрика — не в каждом буллете, а в 1–2 на место.
- [ ] **Глаголы:** Led, Owned, Designed, Built, Improved, Cut, Reduced, Optimized, Implemented, Rolled out, Aligned, Streamlined, Delivered. **Запрещены в начале буллета:** «Worked on», «Responsible for», «Helped with», «Participated in», «Assisted».
- [ ] **Порядок ценности метрик:** деньги и экономия → влияние на пользователя (latency, UX, конверсия) → система (RPS, объёмы, нагрузка) → активность (число релизов/сервисов, самая слабая). Денежных метрик достаточно 2–3 за карьеру; активностные буллеты усилить до цифр или убрать.
- [ ] **Красные флаги цифр:** все числа круглые; абсолютные «100% покрытие», «+1000%»; ложная точность «35,56%», которую не измерить; совсем нет цифр. Цифры реальные, из фактов владельца, объяснимые на интервью. Нет цифр — оцифровать то, что было (время, объём, число пользователей, частота, срок), честно помечая оценку («~»).
- [ ] **Один буллет — одна мысль, до ~25 слов, простой английский.** Рекрутёр просматривает резюме, а не читает; буллет с 3–4 фактами через точку с запятой пропускают. Короткие предложения, простые слова (use, не utilize; start, не commence), активный глагол, конкретика. Проверка: посчитать слова в каждом буллете (`awk`), длиннее 25–30 слов — разбить на два, не теряя цифр.
- [ ] **Один буллет примерно на год работы;** слабые активностные убираем первыми.
- [ ] **Не включать нерелевантный опыт** (подработки, другие профессии), если они не показывают нужные навыки.
- [ ] **Частые смены по ~1 году:** при необходимости объединять места или объяснять проектным характером; места дольше ~1,5 лет выглядят нормально.
- [ ] **Все компании с названием** (не «NDA-компания»): теряется вес бренда. Клиент вместо работодателя — формулировка «для клиента X в рамках компании Y», только если это правда.
- [ ] **Нет Junior/Middle в названиях, если рост виден** (ищут Senior/Staff/Principal); рост по карьере виден.
- [ ] **Навык в блоке Skills = подтверждён в опыте.** Каждый навык из списка встречается хотя бы в одном буллете или строке Technologies места работы. Нет подтверждения — убрать из списка или добавить реальное подтверждение. Отдельный список ключевых слов, скопированный из вакансии, выглядит как массовая рассылка. Проверка: `grep -i` каждого навыка по тексту опыта.
- [ ] **Теги вакансии вшиваем в буллеты** (в начале буллета, 3–5 первых слов), как часть действия («Delivered features in an Agile environment»), не списком и не копипастой вакансии. Одно повторяющееся слово вакансии — 2–3 раза в разных контекстах.
- [ ] **Строка «Technologies / Skills & tools» после каждого места — спорный пункт:** консультант Илья считает, что такие списки мешают человеку читать; данных нет. В шаблоне по умолчанию: 5–7 главных технологий в строке или без неё, если технологии видны в буллетах. Решить по замеру приглашений.
- [ ] **Домены компаний видны** (fintech, healthcare, e-commerce): часть компаний отсеивает без опыта в их домене. Доменные слова (в том числе LLM, IoT, payments) стоят в описании места.
- [ ] **Смена сферы (если применимо):** вести резюме навыками и пользой, а не хронологией; переводить достижения на язык новой профессии; мостик в Summary («Teacher transitioning into Product Management, bringing 5 years of stakeholder management»); доказательства из новой сферы (курсы, пет-проекты, фриланс, волонтёрство).

## 6. Образование, сертификаты, языки, референсы
- [ ] **Образование:** вуз и степень, год — решение по возрастному риску (без годов в резюме допустимо, но в LinkedIn год обязателен: расхождение должно быть осознанным и записанным).
- [ ] **Сертификаты:** только релевантные специальности или громкие, и только реально пройденные.
- [ ] **Языки описательно** (Native / Fluent / Professional Working), не A2/C1. Для европейских вакансий строка нужна.
- [ ] **References:** в резюме не указываем и не пишем «available upon request». Рекомендателей готовим заранее (см. `docs/linkedin/LINKEDIN-ACTIVITY-RULES.md`, раздел 3).

## 7. Что убрать из резюме (проверка на лишнее)
Убрать: фото (по рынку), дату рождения, семейный статус, пол, национальность; «Objective»; «Responsible for / Worked on / Helped with»; «References available upon request»; навыки «MS Word / Google Docs / интернет»; хобби; полный адрес; картинки, шкалы, иконки; фразы-клише («results-oriented», «team player», «passionate»).

## 8. Слова-маркеры ИИ-текста
Не использовать (заменять простым глаголом и цифрой): delve, spearheaded (особенно в каждом буллете), leverage / leveraged, synergy / synergies, meticulous, robust, seamless, cutting-edge, state-of-the-art, tapestry, realm, landscape, «navigate the complexities», конструкция «It's not just X, it's Y». **Тест живости:** прочитать буллет вслух; так бы ты сказал коллеге за обедом? Проверка: `grep -i` по этим словам в файлах профиля. Использовать ИИ как черновик допустимо, если каждую цифру и фразу владелец утвердил и может объяснить.

## 9. Честность и проверяемость
- [ ] Каждая цифра, технология и роль **есть в базе фактов профиля** (`bot/knowledge.md`) и подтверждена владельцем.
- [ ] **«Present» у текущего места** (не закрывать дату, будто уволился): расхождение с LinkedIn и проверкой дороже пользы.
- [ ] Нет «легенды»: подмены компаний, раздутых лет опыта, придуманных проектов.
- [ ] Рекомендатели из резюме и LinkedIn не противоречат друг другу.

## 10. Адаптация под вакансию
- [ ] **Основная версия одна.** Под подходящую вакансию делается копия (лежит рядом с вакансией в `profiles/vacancies/`, не в `resume/`) и меняется только: слова из вакансии в Summary (реально использованные) и порядок слов в Skills (слова вакансии первыми). Опыт, цифры, даты, названия не меняются. Ничего не отправляется без подтверждения владельца.

## 10а. Сопроводительное письмо (необязательно, нужно не всегда)
- [ ] **Когда нужно:** компания просит письмо вместе с резюме, или ты пишешь рекрутёру/менеджеру на почту напрямую (тогда письмо — тело сообщения, резюме во вложении). Переоценивать важность не надо, но и пропускать не стоит.
- [ ] **Главный принцип:** письмо отвечает на вопрос «чем я полезен компании», а не «почему я хочу у вас работать». Мотивация компании тебя нанять, а не твоя.
- [ ] **Формат: 5 предложений, коротко.** Предложение 1 — кто ты и на какую роль; 2 — какую проблему компании ты решал раньше (с цифрой); 3 — как это связано с их вакансией; 4 — один релевантный результат или навык; 5 — лёгкий следующий шаг («рад обсудить, 15 минут на неделе?»). Без «Thanks in advance», без пустой лести, без пересказа резюме.
- [ ] **Версии:** одно универсальное письмо; кастомное только для компании мечты. Факты только из базы профиля.
- [ ] **Спорное, решать по замеру:** блок личности (хобби, семья, интересы) и tech enthusiasm для европейских компаний — совет другого блогера; консультант Илья советует только пользу. Данных нет, можно сделать два варианта и сравнить ответы.
- Источник: пост Ильи 05.02.2026 (Р3) и `profiles/resume/STRATEGY-resume.md`; гипотеза.

## 11. Сверка и выпуск
- [ ] **Резюме = LinkedIn:** названия, даты, цифры, компании, домены, локации совпадают. Расхождение хуже отсутствия цифры: рекрутёр гуглит имя и открывает профиль сразу.
- [ ] Версии `RESUME.md` → `RESUME.html` → `RESUME.docx` / PDF собраны из одного источника; старые версии в `archive-before-<дата>/`.
- [ ] Число страниц проверено в Word/PDF (не оценкой по словам).
- [ ] **Резюме загружается в LinkedIn последним шагом** (когда профиль готов; Settings → Data privacy → Job seeking preferences → Resumes and application data), решение про «Share resume data with hirers» — владельца.

## 12. Замер
- [ ] Версия резюме записана в `analytics.md` (дата, что менялось). Метрики: приглашения, ответы рекрутёров, скрининги. Один блок за раз; сравнивать «до/после» не раньше 1–2 недель.

## Не берём (общее)
Выдуманный опыт и «легенды», накрутка лет, подмена компаний; скрытый текст с ключевыми словами; хитрые фамилии и названия; упоминание рекомендателей и NDA, которых нет; фразы «я не знаю, но добавлю в список навыков» (в Skills только реально известное).
