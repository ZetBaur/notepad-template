# База знаний для поведенческих вопросов (подробности)

Как наполняется:
1. Claude собирает список типичных поведенческих вопросов с собеседований.
2. Claude задаёт владельцу вопросы **по-русски** в чате; владелец отвечает как
   есть (факты, случаи, цифры).
3. Claude документирует ответы в файлах базы (в `profiles/`, в git не попадает)
   и при необходимости заранее готовит версии на обоих языках.
4. Во время интервью база лежит в системном промпте, бот подсказывает по ней.

Жёсткое правило: **никакого вранья и выдумок.** Бот использует только то, что
дал владелец. Если в базе нет данных под вопрос — так и говорит и даёт лишь
структуру ответа, а не придуманные факты.

**Решения (согласованы с владельцем, 2026-09-19):**
- Английский владельца — средний: ему нужны **готовые формулировки, которые он
  зачитывает**. Ответы — разговорные, простыми словами и короткими фразами
  (сокращения, «well», «so», «honestly»), 30–60 сек речи, чтобы не звучало как
  с бумажки. Показывать блоками по 1–2 фразы. Для каждого вопроса заранее
  готовим английский вариант (и русский — собесы бывают и на русском).
  Владелец один раз читает и правит слова под себя.
- Факты хранятся по-русски как их дал владелец + готовый ответ EN/RU рядом.
  Файлы markdown в `profiles/` (в `.gitignore`). Каталог вопросов и статус
  сбора — `profiles/<профиль>/bot/reference/QUESTIONS.md`.
- Вкладок «поведенческое / техническое» **нет** (убраны 2026-09-19 по замеру: Auto
  отвечает верно на 8/8 технических, метка Behavioral ломала технические ответы, см.
  `profiles/research/mode-tabs-measurement-2026-09-19.md`). Тип вопроса модель решает
  сама, а на трёх опасных классах вопросов (про компанию/роль, про уход с текущей
  работы, «опыт с X») приложение само дописывает строку `[Routing hint: …]`
  (`question_hint` в `llm.rs`, по ключевым словам, без задержки); ко всем вопросам
  добавляется строка `[Rule: …]` (только факты профиля, без «high-traffic»/microservices).
  Запреты владельца — в `profiles/bot/FORBIDDEN.md`. **После любой правки промпта или базы
  запускать `cd app/agent-sidecar/eval && ./run.sh`** (тест с реальным промптом, ~4 мин,
  смысл: не дать выдумке вернуться; новые запреты и опасные вопросы дописывать туда же). Замер (Haiku): база 0 / 7k /
  18k токенов не меняет время до первого слова (~0.55–0.75 с), Claude Code
  кэширует системный промпт; первый вопрос сессии ~1–1.3 с скрыт прогревом.
- Вопросы про компанию: заранее (не во время звонка) владелец даёт, что нашёл,
  а Claude дополнительно ищет в интернете и делает карточку компании
  (`profiles/companies/<имя>.md`) + черновик «почему мы» + вопросы к ним. В карточку
  входит **текст вакансии**: бот подстраивает готовые ответы под неё (акцент на
  нужный стек, мобилка/бэкенд/фронт), не выдумывая фактов. В
  приложении карточка выбирается до звонка (поле в настройках).
- Нет ответа в базе: бот пишет «данных нет» + даёт только структуру ответа.
  Такие вопросы бот пишет в файл пробелов, владелец после звонка показывает
  его Claude, и база пополняется.

**Структура с 2026-10-04:** `app/src-tauri/src/knowledge.rs` читает ровно один файл —
`profiles/<профиль>/bot/knowledge.md` (профиль = папка `profiles/<профиль>/`, в ней `bot/knowledge.md`; выбор — переключатель «Profile» в настройках,
пусто = первый по алфавиту). Всё остальное в `<профиль>/bot/` (`reference/`: старые 01-profile, 02-answers с RU, CLAIMS,
QUESTIONS, ANKETA, стратегия общения) и общие `bot/FORBIDDEN.md`, `bot/GAPS.md` в промпт не попадают — список
`EXCLUDED` больше не нужен. Файл знаний = Часть 1 (факты) + Часть 2 (готовые EN-ответы, строки `> `);
русских версий в нём нет (они в `reference/02-answers.md`). Размер 47 КБ вместо 132 КБ.
Раньше (2026-09-19…2026-10-03) код читал все `*.md` верхнего уровня `profiles/` кроме `EXCLUDED`.
+ карточку компании `profiles/companies/<имя>.md`, кэширует и кладёт в конец системного промпта
(`llm.rs`, раздел «CANDIDATE KNOWLEDGE BASE»). Папка с базой: `~/Library/Application Support/dev.notepad.assistant/profiles`
(перенесена туда 2026-09-19, чтобы проект можно было двигать; `profiles/` в репозитории
— символическая ссылка на неё), переопределяется `NOTEPAD_PROFILES`. 
После правки файлов — кнопка «Reload knowledge» в настройках (база кэшируется,
чтобы промпт не менялся и сессия не перезапускалась). **С 2026-09-23 «Reload knowledge»
(и по клику, и при открытии настроек) сам гоняет ту же проверку `bot/FORBIDDEN.md`, что и
`/eval` (`knowledge.rs::check_forbidden` вызывает `eval/check-kb.mjs` из Rust, не
переписан заново — в правилах `FORBIDDEN.md` есть lookahead-регулярки, которых нет в
Rust-крейте `regex`); нарушение показывается прямо в настройках красным текстом. Не
заменяет `/eval` — это только статическая проверка текста базы, не поведения бота.**
Проверено живьём (Haiku,
база ~14k токенов): до первого слова 0.6–1.0 с; ответы дословно из базы, на
вопросы без данных — «No data in the knowledge base.» + структура ответа.
Файл пробелов сделан: бот пишет вопросы без ответа в `profiles/bot/GAPS.md` (проверено живьём).

**Правила речи и перевод вопроса (2026-10-01, перенесено из `interview-app`'s `llm.rs` по решению владельца):**
- Вступительный блок промпта (`build_system_prompt`, `llm.rs`) теперь требует: ответ понятен за 1-2 секунды взгляда («glance» framing); для English-ответов — стиль B1-B2 (не носитель, простые слова и короткие предложения); никогда не заканчивать выводом-моралью («Overall...», «so I know how to...»). Для Russian-ответов B1-B2 не применяется — это родной язык владельца.
- Новая фича: если вопрос пришёл из распознавания речи (`kind: "heard"` на фронте) и язык интервью не русский, модель первой строкой выдаёт `TRANSLATED_Q: <перевод>` — Rust (`read_events`) вырезает эту строку и шлёт отдельным событием `translated-question`, фронт заменяет сырую транскрипцию в панели на русский перевод. Сам ответ на языке интервью не меняется, перевод — только для панели. Порядок между `ask`-запросами и их `delta` синхронизирован очередью `AgentState::translate_flags` (FIFO, один ответ стримится за раз).
- Ещё не прогнаны `/rebuild`+`/eval`+живая проверка — см. `TODO.md`.

**Запреты и тестовые вопросы по профилям (2026-10-04):** если у профиля есть `profiles/<профиль>/bot/FORBIDDEN.md`, проверка базы и `/eval` берут его вместо общего `profiles/bot/FORBIDDEN.md`; набор вопросов — `eval/questions-<профиль>.json`, если есть (запуск: `JH_PROFILE=<профиль> ./run.sh [компания]`). Сейчас так у `backend`.
**Запрещённые слова про опыт (2026-10-04):** список для подсказок «skills question» и напоминания о фактах (`llm.rs`) берётся из `profiles/<профиль>/bot/BANNED-WORDS.txt` (по слову в строке, `#` — комментарий); нет файла — встроенный список (high-traffic, high-load, high-throughput, scalable, microservices, real traffic), файл без слов — запретов нет. Сейчас файл есть у `backend` (пустой).

## Формат ответов и склейка речи (2026-10-09)
- Готовые ответы Части 2 `<профиль>/bot/knowledge.md`: 3–5 коротких фраз по 8–15 слов, каждая с новой строки (вариант A, по просьбе владельца после звонка: длинные гладкие ответы звучали зачитанными). Копия прежнего длинного варианта — `<профиль>/bot/reference/knowledge-LONG-<дата>.md` (в промпт не попадает). Правило в промпте (`llm.rs`): каждое короткое предложение с новой строки, без пустых строк, ответ не длиннее записи в базе.
- Распознавание: сегмент записи режется по паузе 0,7 с или лимиту 20 с (`audio.rs`). Кусок, разрезанный лимитом, держится и склеивается со следующим (сброс при тишине 1,5 с), чтобы бот не отвечал на обрывки. Замер 2026-10-09: конец вопроса → первое слово ≈ 3 с (пауза 0,7 + whisper 0,3–0,7 + LLM 1,4–2,1 с), от длины монолога не зависит.
- **Карточки компаний общие для всех профилей и идут в промпт, поэтому в них НЕТ опыта кандидата** (замер: карточка с опытом кандидата → бот выдумывал факты). В карточке: вакансия, условия, раунды, факты о компании, вопросы к ним. Совпадение опыта, пробелы, черновики «почему вы/почему мы» — в `profiles/companies-notes/<имя>.md` (в промпт не идёт). Опыт — только `<профиль>/bot/knowledge.md`.
- Карточки компаний: первая строка `<!-- recruiter: Имя -->` даёт подпись «Имя — компания» в списке приложения (`list_companies` в `knowledge.rs`), из промпта эта строка вырезается.
